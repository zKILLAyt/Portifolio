## 📌 Sobre o projeto

Este repositório contém meu portfólio pessoal, criado para apresentar minha trajetória, habilidades, projetos e evolução como desenvolvedor.

O projeto começou como um portfólio front-end em HTML, CSS e JavaScript e evoluiu para uma aplicação com **front-end + API própria + PostgreSQL + autenticação administrativa + sistema de feedback**.

A identidade visual segue uma proposta tecnológica, com tema escuro, roxo, ciano, elementos inspirados em interfaces de desenvolvimento, animações e componentes responsivos.

O portfólio também possui uma área de **CyberSecurity — em desenvolvimento**, representando minha próxima área de evolução profissional.

## ✨ Principais funcionalidades

### 🎨 Front-end

- Hero section com identidade visual tecnológica.
- Apresentação profissional e stack de tecnologias.
- Navegação suave entre seções.
- Seção de projetos com filtros por categoria.
- Cards de projetos com links para os respectivos repositórios.
- Animações e efeitos de interação.
- Fundo tecnológico animado.
- Layout responsivo.
- Navegação por teclado nas abas de projetos.
- Suporte à preferência de redução de movimento do sistema.

### ⭐ Sistema de feedback

O portfólio possui um sistema completo para receber avaliações e depoimentos:

- Modal para envio de feedback.
- Nome e cargo/função.
- Avaliação de 1 a 5 estrelas.
- Estrelas interativas.
- Validação do formulário.
- Envio para a API.
- Feedbacks ficam inicialmente como `pending`.
- Apenas feedbacks aprovados são exibidos publicamente.
- Proteções básicas contra abuso de requisições.
- Escape de conteúdo exibido no front-end para reduzir riscos de XSS.

### 🔐 Painel administrativo

O projeto possui uma área administrativa para gerenciamento dos feedbacks:

- Login administrativo.
- Autenticação com JWT.
- Senha armazenada como hash com bcrypt.
- Visualização dos feedbacks pendentes.
- Aprovação de feedbacks.
- Rejeição de feedbacks.
- Exclusão de feedbacks.
- Logout.
- Proteção das rotas administrativas.
- Rate limit para tentativas de login.

## 🗄️ Banco de dados

O sistema de feedback utiliza **PostgreSQL**.

A tabela principal utilizada pelo sistema possui informações como:

- `id`
- `name`
- `role`
- `rating`
- `message`
- `status`
- `created_at`

Os feedbacks são inicialmente registrados como `pending` e passam por análise administrativa antes de serem exibidos no portfólio.

## 🔌 API

### Autenticação

```text
POST /api/auth/login
```

Responsável pelo login administrativo e geração do token JWT.

### Feedbacks públicos

```text
GET /api/feedbacks
```

Retorna os feedbacks aprovados.

### Enviar feedback

```text
POST /api/feedbacks
```

Cria um novo feedback para análise administrativa.

### Feedbacks pendentes

```text
GET /api/feedbacks/pending
```

Rota protegida para o painel administrativo.

### Aprovar feedback

```text
PATCH /api/feedbacks/:id/approve
```

### Rejeitar feedback

```text
PATCH /api/feedbacks/:id/reject
```

### Excluir feedback

```text
DELETE /api/feedbacks/:id
```

As operações administrativas exigem autenticação.

## 🔐 Variáveis de ambiente

O back-end utiliza variáveis de ambiente para evitar que informações sensíveis sejam armazenadas no código-fonte.

Exemplo:

```env
PORT=3000
SUPABASE_DATABASE_URL=...
JWT_SECRET=...
ADMIN_EMAIL=...
ADMIN_PASSWORD_HASH=...
FRONTEND_URL=...
```

> Nunca publique valores reais de `JWT_SECRET`, credenciais do banco, senha administrativa ou outros segredos no GitHub.

## 💻 Como executar localmente

### 1. Clonar o repositório

```bash
git clone https://github.com/zKILLAyt/Portifolio.git
cd Portifolio
```

### 2. Executar o front-end

Como o front-end é baseado em HTML, CSS e JavaScript, ele pode ser aberto por um servidor local ou extensão como Live Server.

### 3. Instalar dependências do back-end

```bash
cd backend
npm install
```

### 4. Configurar o `.env`

Crie um arquivo `.env` dentro de `backend/` com as variáveis necessárias.

### 5. Iniciar o servidor

Modo desenvolvimento:

```bash
npm run dev
```

Produção:

```bash
npm start
```
